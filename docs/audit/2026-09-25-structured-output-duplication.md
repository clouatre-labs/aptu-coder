# Audit: structured output duplication across MCP tools

Date: 2026-09-25

Scope: the five tool handlers in [crates/aptu-coder/src/lib.rs](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/lib.rs) and [crates/aptu-coder/src/tools/](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/tools/) that emit both a text block and `structuredContent` with a declared `outputSchema`: `analyze_file`, `analyze_module`, `analyze_symbol`, `edit_overwrite`, `edit_replace`.

Context: the aptu-coder MCP server is consumed exclusively by autonomous coding agents. Within the aptu-coder customer base (autonomous coding agents such as pi, goose, and claude code, whose harnesses surface only the text `TextContent` block to the model), `structuredContent` is observed to be effectively unread by the agent loop, so its bytes are pure token cost; this is an observed property of those harnesses, not an inherent MCP property — other MCP clients may consume `structuredContent`, though no plausible external consumer is currently known. The primary metric is `est_output_tokens` (`output_chars / 4`), defined in [docs/METRICS.md](https://github.com/clouatre-labs/aptu-coder/blob/main/docs/METRICS.md). Note a scope correction from the original audit request: `find`, `grep`, and `read` tools do not exist in `lib.rs`. `analyze_directory` and `exec_command` are excluded as merged precedents ([#1640](https://github.com/clouatre-labs/aptu-coder/pull/1640) and [#1641](https://github.com/clouatre-labs/aptu-coder/pull/1641)), consistent with the earlier sizing work in [docs/audit/2026-09-25-small-codebase-fit.md](https://github.com/clouatre-labs/aptu-coder/blob/main/docs/audit/2026-09-25-small-codebase-fit.md); this audit does not re-litigate that document's S2 finding.

## Decision rule

- **MIRROR** (roughly 100 percent duplicated): delete the `structured_content` assignment and the `output_schema = schema_for_type::<T>()` decorator entry together, in the same PR. Pattern: [#1640](https://github.com/clouatre-labs/aptu-coder/pull/1640).
- **DUPLICATE+METADATA** (partially duplicated, with some unique fields): prune to a metadata-only view struct, regenerate the `outputSchema` in lockstep with the view type, and add a key-set drift-guard test. Pattern: [#1641](https://github.com/clouatre-labs/aptu-coder/pull/1641).
- **UNIQUE** (no text equivalent): keep unchanged.

Duplicate shares below are estimates based on handler inspection and prior schema sizing, not exact measurements.

## Issue drafts

### analyze_symbol: delete mirrored structuredContent (MIRROR)

`analyze_symbol` serializes `FocusedAnalysisOutput` whose `formatted` field is byte-for-byte the text block, while `prod_chains`, `test_chains`, `outgoing_chains`, and `def_use_sites` are already rendered into `formatted`, and the only field not in `formatted` (`next_cursor`) is echoed in the text as a `NEXT_CURSOR` line. This roughly doubles the server's largest payloads (symbol call graphs reach multi-thousand-char outputs) on every call. Proposed change: delete the `structured_content` assignments at both return sites in [crates/aptu-coder/src/tools/analyze_symbol.rs](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/tools/analyze_symbol.rs) and the `output_schema = schema_for_type::<FocusedAnalysisOutput>()` entry in the `#[tool]` decorator in [crates/aptu-coder/src/lib.rs](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/lib.rs), following the [#1640](https://github.com/clouatre-labs/aptu-coder/pull/1640) precedent. Acceptance criteria: the `outputSchema` is regenerated (removed) in the same PR as the `structuredContent` removal; a drift-guard test confirms the serialized key set is gone from tool listings; migrated tests cover cursor parsing from the text block; `est_output_tokens` before/after telemetry shows approximately 50 percent per-call reduction on the tool's output plus removal of the always-on schema tokens.

### analyze_file: delete mirrored structuredContent (MIRROR)

`analyze_file` builds `FileAnalysisOutput` where `formatted` equals the text block, and `path`, `line_count`, `next_cursor`, and `semantic` are all rendered in the text, making the `structuredContent` a full duplicate. The per-call saving is approximately 433 tokens at the median (1,733 chars text) plus 989 tokens of always-on `outputSchema`. Proposed change: delete the `result.structured_content` assignment at [analyze_file.rs:437](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/tools/analyze_file.rs) and the `output_schema = schema_for_type::<FileAnalysisOutput>()` entry at [lib.rs:446](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/lib.rs) together, per [#1640](https://github.com/clouatre-labs/aptu-coder/pull/1640), and update the tool description to state that output is returned as a text block only. Acceptance criteria: paired structuredContent/outputSchema removal in one PR; the `semantic` fields-default and fields-requested behaviors currently asserted in `analyze_file_fields_summary.rs` and `integration_tests.rs` are re-asserted against text markers in the same PR; a drift-guard test asserts the tool's `outputSchema` is absent; `est_output_tokens` before/after telemetry recorded in the PR description.

### analyze_module: delete mirrored structuredContent (MIRROR)

`analyze_module` serializes `ModuleInfo` verbatim into `structuredContent` on both the success branch ([analyze_module.rs:250](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/tools/analyze_module.rs)) and the unsupported branch (:161), while the text block is `format_module_info(mi)` rendered from the same struct, so the duplication is total and the migration cost is near zero because no test asserts this tool's `structuredContent`. Proposed change: delete both `structured_content` assignments and the `output_schema = schema_for_type::<ModuleInfo>()` entry at [lib.rs:564](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/lib.rs) in one PR per [#1640](https://github.com/clouatre-labs/aptu-coder/pull/1640). Acceptance criteria: lockstep structuredContent/outputSchema removal; a drift-guard test asserts no `outputSchema` is advertised for the tool; existing module tests pass unchanged; `est_output_tokens` before/after telemetry shows the per-call saving on typical module indices.

### edit_overwrite: delete mirrored structuredContent (MIRROR)

`edit_overwrite`'s success `structuredContent` is `EditOverwriteOutput { path, bytes_written }`, a 1:1 restatement of the two-line text block `Wrote {bytes_written} bytes to {path}`; the overhead is small (roughly 15 tokens per call) but the fix is free. Error-path `structuredContent` payloads are out of scope here and remain untouched. Proposed change: delete the `structured_content` assignment at [edit_overwrite.rs:202](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/tools/edit_overwrite.rs) and the `output_schema = schema_for_type::<EditOverwriteOutput>()` entry at [lib.rs:616](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/lib.rs) together per [#1640](https://github.com/clouatre-labs/aptu-coder/pull/1640). Acceptance criteria: lockstep paired removal; a drift-guard test asserts no success-path `outputSchema`; the success-path assertions in `edit_working_dir.rs` move to text regex while the error-path structured assertions are unchanged and green; `est_output_tokens` before/after telemetry recorded.

### edit_replace: prune structuredContent to a metadata view (DUPLICATE+METADATA)

`edit_replace`'s `EditReplaceOutput` bulk-duplicates `path`, `bytes_before`, `bytes_after`, and `occurrences_replaced` that already appear in the text block, but also carries a unique machine-consumable blake3 `content_hash` and per-edit batch results. Proposed change: introduce a metadata-only view struct (path, sizes, occurrences, `content_hash`) with a `From<&EditReplaceOutput>` impl, set `structured_content` from the view at [edit_replace.rs:698](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/tools/edit_replace.rs), regenerate `output_schema` at [lib.rs:657](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/lib.rs) in lockstep, and update the tool description, following the [#1641](https://github.com/clouatre-labs/aptu-coder/pull/1641) pattern; per-edit results move to the text block or survive only as counts. Acceptance criteria: lockstep schema regen to the view type; a serialized key-set drift-guard test modeled on `shell_output_metadata_key_set_matches_shell_output_subset` plus a `From` field-copy test; `edit_replace_errors.rs` batch schema test updated to the view type; `est_output_tokens` before/after telemetry shows removal of the per-edit bulk while preserving the hash contract.

## Sequencing recommendation

Ordered by estimated `est_output_tokens` impact, largest first:

1. `analyze_symbol` — largest per-call payloads (call graphs, worst case roughly 3.4k tokens), so the roughly 50 percent saving is the biggest absolute win, plus 733 tokens of always-on schema removal.
2. `analyze_file` — roughly 433 tokens per median call plus 989 tokens of schema removal; highest call frequency among the analyze tools.
3. `analyze_module` — clean 100 percent mirror with zero test migration; a quick win.
4. `edit_overwrite` — tiny per-call overhead but free to remove.
5. `edit_replace` — prune (not delete) last, since it carries the unique `content_hash` contract and the drift-guard test migration.

## No-action list (UNIQUE payloads)

The following `structuredContent` payloads are explicitly out of scope and must not be re-opened by future audits. They carry a machine-consumable error taxonomy with no text equivalent: error-path `structuredContent` fields `ioErrorKind`, `ioErrorSource`, `suggestedAction`, and `errorCategory` (asserted in [edit_working_dir.rs](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/tests/edit_working_dir.rs) and produced via `err_to_tool_result` in [common.rs](https://github.com/clouatre-labs/aptu-coder/blob/main/crates/aptu-coder/src/tools/common.rs)). These stay unchanged.

## MCP coupling note

Under the MCP specification revision labeled 2026-07-28 (the revision verified during [#1640](https://github.com/clouatre-labs/aptu-coder/pull/1640)), a tool that declares an `outputSchema` must return `structuredContent` conforming to it; `outputSchema` itself is optional, so omitting both `structuredContent` and `outputSchema` is fully conformant. All MIRROR recommendations above delete the pair in the same PR, which is spec-safe. This was verified during [#1640](https://github.com/clouatre-labs/aptu-coder/pull/1640) and is consistent with the server's conformance work in [docs/audit/2026-08-01-mcp-spec-2026-07-28.md](https://github.com/clouatre-labs/aptu-coder/blob/main/docs/audit/2026-08-01-mcp-spec-2026-07-28.md).

## Question

The v19 benchmark program is complete. The pre-registered claim gate returned NOT-SUPPORTED. What did the program actually establish, what does it rule out, and how should the project's positioning change in response?

## Answer (short)

1. **The headline claim is dead, cleanly.** In agentic loops (bash + rg + read available) on structural fan-in tasks, tree-sitter structural analysis shows no measurable F1 gain: pooled paired F1 diff (mcp - native) mean -0.071, 95% CI [-0.179, +0.038], N=20 pairs, gate NOT-SUPPORTED per the pre-registered rule. In-loop token-savings and quality claims for agentic loops are not supported by this program.
2. **The program's highest-value artifact is not a performance number; it is deterministic anchor verification.** `verify_anchors` (A6/A9a, now shipped as the `aptu-coder_verify_anchors` MCP tool) turned anchor fabrication from an invisible failure mode into a checkable one -- and fabrication turned out to be the dominant quality failure in BOTH arms.
3. **The pivot is to deterministic verification, premise grounding, and non-agentic consumers.** The v12/v13 benchmark token savings (up to 59%) remain valid for the conditions they measured; the v19 result scopes where structural analysis belongs: as ground truth for premise formation, citation verification, and oracle-grade scoring, not as an in-loop efficiency lever for agents that already have shell search.

## The story arc

**v18 measured a null by design.** The v18 fixture was filtered for rg-vs-tree-sitter agreement; every task was solvable by `rg` plus one grep level. The gateway smoke measured 0/4 MCP activation against an 80% target, and the fixture was diagnosed as "ripgrep-optimal and adversarial to structured analysis" ([FAIR-DESIGN](https://github.com/clouatre-labs/aptu-coder/blob/main/docs/benchmarks/v19/FAIR-DESIGN.md)). What v18 actually measured was tool-selection failure, not tool value.

**v19 was designed to fix exactly that** (#1623/#1617 methodology; execution under #1681): real Django codebases instead of a synthetic fixture, a grep-hostile fan-in tier where rg output floods context, F1 against a tree-sitter AST oracle instead of subjective scoring, cost-at-iso-quality per BudgetBench instead of raw mean comparison, and a fail-closed activation gate (F3) before any F1 interpretation.

**The amendment trail is the story.** A1 ratified the fair design. A2 dropped the LLM anchor-adjudication layer after it failed its own calibration gate (agreement 0.733 < 0.90) -- a documented negative result on LLM verification oracles. A3/A4 collapsed the ladder to a single hop-2 fan-in tier after output-boundedness invalidated the hop-3 tier. A5 voided every prior tool-arm session on a cache-poisoning bug and installed a permanent tool-as-oracle pre-sealed gate. A6/A9a replaced the broken fabricated-anchor check with deterministic snapshot-verified anchor verification. A7/A7b/A8 turned three harness defects (turn cap, silent wait-deadline kills, provider-error sessions) into repair policies. A9 ratified caps as-is from a probe. A10/A11 pool exhaustion (exactly 8 viable symbols on the pinned snapshot) forced a stratified two-snapshot design. The first stratified attempt was halted fail-closed by the activation gate when an unpinned runtime update silently moved the tool surface behind an MCP gateway.

**The final result.** After the A12 surface fix (adapter pin, directTools config, pre-sealed surface gates), the F3 activation gate PASSED (11/11 and 5/5 scorable tool-arm sessions with direct tool calls; 262 direct calls). The treatment was real this time -- and the pre-registered gate still read NOT-SUPPORTED: pooled repair-adjusted paired F1 diff -0.0709, 95% CI [-0.1794, 0.0377], which includes 0 with the point estimate in native's favour, against a gate requiring the CI to exclude 0 in mcp's favour and a mean diff >= 0.1. Total program spend, including every invalidated and repair run, is fully ledgered at a few dollars.

## Lessons

1. **In agentic loops with bash + rg, tree-sitter structural analysis shows no measurable F1 gain on structural fan-in tasks.** Evidence: the N=20 stratified paired result above ([nrun closeout](https://github.com/clouatre-labs/aptu-coder/blob/main/docs/benchmarks/v19/results/tasks-fanin-hop2-nrun/README.md)); correct cells (F1 >= 0.75, snapshot-verified) were 2 vs 2 across arms. When an agent can grep, the structural tool does not add answer quality on these tasks, and its schema overhead plus tool turns cost ~1.4x per pair-session.
2. **Tool activation is a config problem, not a model problem.** v18's 0/4 activation was read as model tool-choice failure; v19 proved it was surface wiring. With `directTools` surfacing and the ratified one-sentence availability note, activation hit 1.0 (and a runtime drift that silently gateway-mediated the tools was caught and fixed). The v18 "models ignore unfamiliar tools" conclusion was partly wrong: models use tools that are directly surfaced.
3. **Anchor fabrication is the dominant quality failure mode in BOTH arms, and deterministic anchor verification is the program's highest-value artifact.** Fabricated `path:line` citations appeared in 18/24 stratum-1 sessions under the strict word-boundary verifier, across both arms; verify-repair fixed only a minority of cells. `verify_anchors` (file exists, line in range, word-boundary symbol within the window, against the snapshot) is deterministic, zero-LLM, and now a shipped MCP tool.
4. **Harness discipline works.** Four fail-closed halts (A5 cache-poisoning void, A7b invisible wait-deadline kills, the A11 pool-exhaustion halts, the activation-gate drift halt) each caught a real validity threat before it contaminated a sealed result. Every halt cost metered spend and zero invalid conclusions.
5. **Negative results are only publishable when the claim gate is pre-registered.** The A11 decision rule ("supported IFF repair-adjusted pooled 95% CI excludes 0 in mcp's favour AND mean paired diff >= 0.1") was ratified before spend. Because it was, this program ends with a clean NOT-SUPPORTED instead of a post-hoc argument. The gate also forces honesty about power: post-hoc power at the observed effect was 0.277; the design was under-powered for the ratified 0.1 gap -- the result is "no measured gain," not "proven zero."

## Pivot: where aptu-coder's analysis goes from here

Direction, not yet measured end-to-end:

- **Deterministic ground truth for premise formation in multi-agent workflows.** Scout-style agents that gather structural facts before work starts can use `analyze_symbol` call graphs as a citable premise layer, with premises checked against the same tree-sitter oracle rather than trusted.
- **Citation verification.** `verify_anchors` as a fabrication killer: any agent output containing `path:line` claims can be verified deterministically against the working tree. This is the single most transferable artifact of the program.
- **Non-agentic MCP consumers.** The v12/v13 token-savings conditions (single focused tasks, no shell search loop) remain the supported environment for the comprehension-layer positioning; IDE assistants, CI jobs, and scoring pipelines fit here.
- **Oracle-grade scoring infrastructure.** The A5 tool-as-oracle gate showed where tool and oracle semantics align exactly (F1 = 1.000 on unambiguous symbols); the scorer, snapshot pinning, and fail-closed gate machinery are reusable benchmark infrastructure.

Explicitly NOT supported by this program: in-loop token-savings claims and answer-quality claims for agentic loops with shell search tools. The v19 result is scoped to zai/glm-5.3-flash on Django fan-in/hop-2 Track A; other models and task families are unmeasured. The v12/v13 benchmark numbers stand for the conditions they measured and should not be generalized to agentic-loop conditions.

**End-to-end workflow hypothesis (not a result).** The working hypothesis going forward is that Scout/Guard grounding on deterministic structural facts produces higher code quality and longer shelf life in real multi-agent runs. This has not been measured; it is to be evaluated against real usage data (metrics JSONL), not asserted from this program.

## Purpose

Point-in-time conformance audit of aptu-coder against the MCP 2026-07-28 GA specification, covering every changelog item. Verdicts are grounded in the fetched official changelog and in verified behavior of the installed `rmcp` 3.9.0 crate source (`~/.cargo/registry/src/.../rmcp-3.9.0/`), not training data.

## Changelog Coverage and Verdicts

### Major changes

| Changelog item | Verdict | Evidence |
|---|---|---|
| 1. Stateless core: no sessions, no `Mcp-Session-Id` (SEP-2567) | PASS (transport-level; stdio primary) | aptu-coder serves over stdio via rmcp 3.9.0; no session-header code paths remain after the 2026-08-01 audit cleanup |
| 2. Stateless protocol: no `initialize` handshake; version + capabilities in `_meta` (SEP-2575) | GAP (upstream) | rmcp 3.9.0 still runs the initialize handshake server-side; server cannot opt out. Tracked since the 2026-08-01 audit (C02); blocked on rmcp |
| 3. `server/discover` (SEP-2575) | GAP (upstream) | rmcp 3.9.0 `ServerHandler` does not expose a `discover` method; stdio backward-compat probe covers clients |
| 4. `subscriptions/listen` replaces GET + `resources/subscribe` | PASS (N/A) | aptu-coder advertises no subscription or listen capability and never used the removed methods |
| 5. Removal of `ping`, `logging/setLevel`, `notifications/roots/list_changed` | PASS | Logging dead code was deleted after the 2026-08-01 audit (C01); no `ping` or roots-changed notification code exists |
| 6. Tasks moved to the `io.modelcontextprotocol/tasks` extension (SEP-2663) | PASS (N/A) | aptu-coder implements no tasks and advertises no task capability |
| 7. Multi Round-Trip Requests `InputRequiredResult` (SEP-2322) | PASS | `ReadResourceResponse::InputRequired` is produced by the rmcp 3.9.0 typed surface; the server returns `resultType: "input_required"` interim results where applicable |
| 8. Required `resultType` on all results (SEP-2322) | PASS (server side) | Server always emits typed results carrying `resultType`; client-side tolerance for its omission is not applicable |
| 9. SSE resumability removal (SEP-2575) | PASS (N/A) | No SSE transport code in aptu-coder |

| 3. Deterministic `tools/list` ordering (SHOULD) | PASS | Tool registry emits tools in a fixed registration order |
| 4. `Mcp-Method`/`Mcp-Name` headers, `x-mcp-header` (SEP-2243) | PASS (N/A) | Streamable HTTP transport not used; stdio carries no HTTP headers |

| 6. | 7-9. Authorization (RFC 9207 `iss`, `application_type`, credential binding) | PASS (N/A) | No OAuth/authorization-server surface in aptu-coder |
| 10. Loosened schema keyword rules (SEP-2106) | PASS (upstream) | Tool schemas are generated by schemars (locked 1.2.3) via rmcp; JSON Schema 2020-12 keywords accepted |

| 12. Error-code allocation policy (`-32000..-32019` impl-defined, `-32020..-32099` spec-reserved) | PASS | aptu-coder uses only standard JSON-RPC codes and spec constants from rmcp; no implementation-defined codes in the reserved range. `RESOURCE_NOT_FOUND (-32002)` remains grandfathered SDK usage inside rmcp and is kept only in the metrics classifier |

## Summary

GA conformance is complete on every item within aptu-coder's control. The two open gaps (stateless `_meta` handshake removal and protocol-level `CacheableResult` fields) are rmcp 3.9.0 API limitations, already tracked from the 2026-08-01 audit, and carry no client-visible non-conformance over stdio today. SEP-2164 error-code renumbering is implemented in this change with telemetry behavior preserved via the cache-miss discriminator.
